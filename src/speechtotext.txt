    1️⃣ Check Your Pi’s RAM

Total RAM: free -h
Example output:

              total        used        free      shared  buff/cache   available
Mem:           7.8G        2.1G        3.2G        0.1G        2.5G        5.2G
Swap:          2.0G        0.0G        2.0G


available = memory you can safely use without slowing down the system.

If you have >2 GB free, you could try the 1.8 GB Vosk model, but leave some RAM for SQL and other processes.

2️⃣ Check CPU Load

Command: top or htop

Look at %CPU for your processes.

If CPU is consistently high (~90–100%), adding a big Vosk model may cause lag.

Tip: Vosk is CPU-intensive when transcribing in real-time, especially for bigger models.

3️⃣ Check SQL Server Usage

Run your SQL server normally and monitor memory & CPU usage (htop).

Look at how much RAM it uses under normal workloads.

Example:

SQL server using 1 GB RAM → leaves ~7 GB free on an 8 GB Pi.

That’s enough for the 1.8 GB Vosk model (~1.8 GB in RAM plus small overhead).

4️⃣ Testing Safely

Start with lightweight model: en-us-0.22-lgraph (128 MB).

Run your server and SQL as normal.

Monitor RAM and CPU. If everything stays below ~70–80% utilization:

You can try the 1.8 GB model.

If RAM usage gets too high, stick with the lightweight model to avoid swapping (which will slow down both SQL and Vosk).
